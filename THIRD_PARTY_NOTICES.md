# Third-Party Notices

microtel itself is licensed under the Apache License 2.0 ([`LICENSE`](LICENSE),
[`NOTICE`](NOTICE)). This file reproduces the licenses of the third-party code
microtel **vendors** — code that is compiled into microtel's shipped archives or
installed as headers, and therefore travels with every binary and every source
distribution.

Libraries microtel merely *links against* at runtime (nghttp2, OpenSSL, zlib and
the optional spdlog) are not vendored: they are supplied by the consumer's
system and carry their own notices there. [`NOTICE`](NOTICE) names them.

| [upb](#upb) | BSD-3-Clause | compiled into `libmicrotel_upb_runtime.a` | `third_party/upb/` |
| [utf8_range](#utf8_range) | MIT | compiled into `libmicrotel_utf8_range.a` | `third_party/utf8_range/` |

| [opentelemetry-proto](#opentelemetry-proto) | Apache-2.0 | schema only; generated accessors compile into `libmicrotel_upb_gen.a`, and for the leaf into `libmicrotel_nanopb_gen.a` | `proto/` |
| [nanopb](#nanopb) | zlib | leaf only: compiled into `libmicrotel_nanopb.a` when the leaf is built with `MICROTEL_LEAF_ENCODER=nanopb` | `third_party/nanopb/` |

Per [ICP 0020](docs/icps/0020-install-and-package-config.md) Decision 4, upb and
utf8_range ship with every globally-visible symbol renamed to a `microtel_`
prefix. The rename is microtel's, applied by a force-included header; the
vendored sources themselves are byte-identical to upstream and remain under the
licenses reproduced below.

## Keeping this file true

This file is hand-maintained, not generated. A pin bump under `third_party/` or
`proto/` updates the provenance table and, if upstream relicensed, the license
text alongside it — step 5 of each vendored directory's own "Refreshing the pin"
procedure.

`cmake --install` places [`LICENSE`](LICENSE), [`NOTICE`](NOTICE) and this file
in `<prefix>/share/licenses/microtel/`, so an installed tree carries the same
attribution a source checkout does (issue #191).
